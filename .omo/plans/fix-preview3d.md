## 現状の問題

### 1. `selectionBounds` が無視されている
`Preview3D` は `selectionBounds` プロパティを受け取っているが、内部では使用していない。
常に東京23区のハードコードされたタイルセット URL を読み込むだけ：
```ts
const tilesetUrl = 'https://api.plateauview.mlit.go.jp/datacatalog/3dtiles/13-bldg-lod1-2025/tileset.json'
```

### 2. シーンが完全再生成される
`useEffect` の依存配列が `[selectionBounds, sceneRef]` になっており、選択範囲が変わるたびに Three.js のシーン・カメラ・レンダラー・コントローラがすべて作り直される。

### 3. カメラが選択範囲を向いていない
タイルセットの中心にカメラを合わせる処理はあるが、これはタイルセット全体の中心であり、ユーザーが選択した特定の範囲ではない。

### 4. エラー処理・ローディング表示が不十分
`load-error` イベントはコンソールにしか出力されず、ユーザーには何も表示されない。

### 5. タイルセット URL が機能しない可能性
東京23区のタイルセット URL が現在有効か不明。ネットワークエラーの可能性がある。

## 修正方針

### 方針 A: カメラを選択範囲に合わせる（最小限の修正）

タイルセットは東京23区固定のまま、選択範囲の中心にカメラを移動させる。
選択範囲が東京23区外の場合は警告を表示する。

### 方針 B: 動的タイルセット読み込み（完全な修正）

選択範囲の座標から該当する PLATEAU タイルセットを特定し、動的に読み込む。
これには PLATEAU のカタログ API との連携が必要。

**今回は方針 A を採用する。**
理由：
- 最小限の変更で選択範囲の確認が可能になる
- PLATEAU の全データセット対応は別途大規模な調査・実装が必要
- まずは「選択した範囲がどこか」が視覚的に確認できる状態にすることが優先

## 実装ステップ

### Step 1: シーンの分離（初期化と更新を分ける）

現在の `useEffect` を2つに分離する：

1. **シーン初期化用 `useEffect`**（マウント時のみ）
   - Three.js シーン・カメラ・レンダラー・コントローラを作成
   - グリッドを追加
   - アニメーションループを開始
   - クリーンアップはアンマウント時のみ

2. **タイルセット読み込み用 `useEffect`**（`selectionBounds` 変更時）
   - タイルセットを読み込み
   - 選択範囲の中心にカメラを配置
   - 既存のタイルセットがある場合は削除してから新規読み込み

### Step 2: 選択範囲の中心計算

```ts
function getSelectionCenter(bounds: SelectionBounds) {
  const centerLon = (bounds.west + bounds.east) / 2
  const centerLat = (bounds.south + bounds.north) / 2
  return { lon: centerLon, lat: centerLat }
}
```

### Step 3: カメラ位置の更新

タイルセットの座標系（ECEFまたはローカル）に合わせてカメラを配置する。
PLATEAU の 3D Tiles は通常 WGS84/ECEF 座標系を使用しているため、
選択範囲の中心座標を ECEF に変換してカメラ位置を設定する必要がある。

ただし、現在の実装では `tilesRenderer.group.position` で原点合わせをしており、
タイルセットのローカル座標系で扱われている。

簡易的な方法として：
1. `load-root-tileset` イベントでタイルセットの中心と半径を取得（既存）
2. 選択範囲の中心がタイルセット内に収まっているか確認
3. カメラを選択範囲の中心に向ける

### Step 4: ローディング・エラー表示の追加

`Preview3D` 内に以下の UI 状態を追加：
- `isLoading` - タイルセット読み込み中
- `error` - 読み込み失敗時のメッセージ
- `noSelection` - 選択範囲がない場合のガイダンス

### Step 5: タイルセット URL の検証・修正

現在の URL が有効か確認し、必要に応じて代替 URL に変更する。
PLATEAU View の API エンドポイントが変更されている可能性があるため、
最新のドキュメントを確認する。

## 技術的な懸念事項

### 1. 座標変換
PLATEAU の 3D Tiles は WGS84/ECEF 座標系。選択範囲の中心（度単位）を Three.js のワールド座標に変換する必要がある。

Cesium の `Cartesian3.fromDegrees` を使って ECEF 座標を取得し、
タイルセットの原点オフセットを考慮してカメラ位置を計算する。

### 2. タイルセットの範囲外選択
ユーザーが東京23区外を選択した場合、タイルセットにデータが存在しない。
この場合は「選択範囲がデータ対象外です」というメッセージを表示する。

### 3. パフォーマンス
タイルセットの読み込みは非同期的。選択範囲を変更するたびにタイルセットを再読み込みすると遅い。
キャッシュ機構や、読み込み中の表示が必要。

## テスト計画

1. **選択範囲なしでプレビュータブを開く** → 「範囲を選択してください」メッセージが表示される
2. **地図で範囲を選択後、プレビュータブを開く** → ローディング表示後、3Dモデルが表示される
3. **選択範囲を変更後、再度プレビュー** → カメラが新しい範囲の中心に移動する
4. **東京23区外を選択** → 「データ対象外」メッセージが表示される
5. **ネットワークエラー時** → エラーメッセージが表示される
